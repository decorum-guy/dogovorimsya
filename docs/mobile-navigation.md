# Нижняя навигация и прокрутка на телефоне

Исправление по сообщению владельца от 8 ноября 2026: нижнее меню при прокрутке могло подниматься в середину экрана и перекрывать элементы.

## Причина и решение

До исправления `.mobile-nav` использовала position:fixed, bottom:0 и backdrop-filter; скроллился весь документ. Навигация уже находилась вне трансформируемого PullToRefresh, поэтому перенести её из него не было решением.

Для iOS/WebKit описан совпадающий класс ошибок fixed/sticky при прокрутке: [WebKit 301172](https://bugs.webkit.org/show_bug.cgi?id=301172). На физическом устройстве владельца точная версия и последовательность не воспроизведены; связь с конкретной ошибкой WebKit — вероятное объяснение, а не результат отладки его телефона.

Исправление устраняет саму зависимость меню от viewport-fixed/sticky. На ширине до 760 px авторизованный экран `.session-shell.authenticated` занимает 100dvh (100vh fallback). Баннеры занимают собственное место, `.app-layout` — оставшееся. Внутри две строки grid: minmax(0,1fr) для main и auto для меню. Прокручивается только main; меню находится в обычном потоке, без размытия фона и без JS-пересчёта координат. Высота меню, включая safe-area, вычитается раскладкой: контент не уходит под него.

PullToRefresh читает scrollTop main и window.scrollY (для десктопа), чтобы жест не запускался посреди мобильной страницы. Переходы навигации сбрасывают оба контейнера, открытое модальное окно блокирует прокрутку main через body.modal-open. На десктопе остаётся прежняя прокрутка документа; экран входа и галерея не переводятся в ограниченную оболочку.

Не возвращать fixed/sticky/transform-позиционирование нижней навигации и не исправлять проблему увеличением z-index: это не устраняет дрейф и перекрытие. Не менять контейнер прокрутки без адаптации жеста обновления, переходов и блокировки под модальным окном.

## Проверки

- Локальное демо, Chrome с мобильным viewport 393×852: на середине и в конце ленты scrollY документа = 0, scrollTop main меняется, нижняя грань меню = 852, нижняя грань main совпадает с верхней гранью меню = 788.
- Последняя карточка открывается нажатием; обсуждение работает, main блокируется при открытом dialog. При переходе в «Мы вдвоём» main возвращается к началу.
- Длинная страница профилей и уменьшение высоты до 640 px: меню остаётся у новой нижней границы, main заканчивается над ним.
- На 320×740 нет горизонтального переполнения, кнопки и боковое меню доступны.
- На 1280×900 меню скрыто, документ прокручивается, main не становится отдельным scroll-контейнером.
- Существующие 91 тест и TypeScript/production-сборка проходят. Схема, серверные права и личные данные этим изменением не меняются.

Это обход проблемы раскладкой, проверенный на перечисленных сценариях. Chrome на Mac не эмулирует инерционный скролл, клавиатуру, изменение системных панелей и safe-area настоящей iOS/PWA. Окончательное подтверждение исходного симптома требует телефона владельца. Встроенный браузер в этой сессии не отвечал на команды; визуальная проверка выполнена в доступном Chrome, а не выдана за тест Safari.
