# Развёртывание на VPS

Подготовленные файлы не означают, что сервер уже настроен. Домен, IP, ОС, свободные порты и способ SSH-входа нужно получить от владельца. Перед запуском проверить текущие сайты, обратный прокси, Docker/Compose, порты и место на диске. Существующие сервисы не останавливать для освобождения портов без отдельного решения владельца.

## Домен в REG.RU

Для нового домена можно использовать бесплатные DNS `ns1.reg.ru` и `ns2.reg.ru`. В ресурсных записях создать `A`, поддомен `@`, значение — реальный публичный IPv4 VPS. Если нужен `www`, добавить `A` для `www` на тот же IP и настроить этот хост в обратном прокси. IPv6/AAAA указывать только при фактически настроенном IPv6 сервера.

[Инструкция REG.RU](https://help.reg.ru/support/dns-servery-i-nastroyka-zony/rabota-s-dns-serverami/kak-privyazat-domen-k-ip-adresu). Обновление DNS может занять до 24 часов. Доступность HTTPS проверяется после того, как DNS указывает на нужный VPS.

## Если Docker и Compose доступны

Команды выполняются из корня клона проекта на сервере. Начальная настройка:

```sh
cp deploy/.env.example deploy/.env
```

В `deploy/.env` вписать купленный домен без `https://`, например `DOMAIN=example.com`. `APP_BIND_PORT` должен быть свободным локальным портом. Этот файл не коммитится.

```sh
docker compose --env-file deploy/.env build app
docker compose --env-file deploy/.env run --rm app node build/scripts/accounts.js
```

Вторая команда интерактивно создаёт первый аккаунт автора-администратора. Реальные пароли вводит владелец; они не отображаются и не передаются аргументами. Второй аккаунт создаётся уже через сайт по выданному администратором коду.

Вместо интерактивного ввода можно подготовить первый вход без задания пароля на сервере:

```sh
docker compose --env-file deploy/.env run --rm -T app node build/scripts/accounts.js bootstrap
```

Команда работает только на пустой базе, создаёт автора-администратора с логином `owner` и временным именем «Автор» и один раз выводит стартовый код восстановления в текущую SSH-сессию. Начальный пароль случаен и никому не показывается. Владелец открывает на сайте «Забыли пароль? Есть код», вводит код и задаёт свой пароль. Имя меняется в профиле. Bootstrap не изменяет уже существующие аккаунты; код и ответ команды нельзя помещать в Git или публичные журналы.

Если порты 80 и 443 свободны и обратного прокси пока нет:

```sh
docker compose --env-file deploy/.env --profile https up -d
```

Caddy получает сертификат для DOMAIN и перенаправляет HTTP на HTTPS. DNS должен быть направлен на VPS, а порты 80/443 доступны снаружи. Встроенный Caddyfile обслуживает основной домен; `www` добавляется отдельно при необходимости. Сертификаты хранятся в постоянном томе.

Если уже есть Nginx/Caddy/другой прокси:

```sh
docker compose --env-file deploy/.env up -d app
```

Существующий прокси нужно настроить на `127.0.0.1:APP_BIND_PORT` и HTTPS для выбранного домена. Приложение не публикует порт на внешнем интерфейсе. COOKIE_SECURE включён, Origin привязан к HTTPS-домену. TRUST_PROXY=1 предполагает один доверенный прокси непосредственно перед приложением.

Если существующий прокси сам находится в Docker, можно подключить только приложение к его сети: добавить в `deploy/.env` `PROXY_NETWORK=имя_существующей_сети` и использовать оба compose-файла:

```sh
docker compose --env-file deploy/.env -f compose.yaml -f deploy/compose.proxy.yaml up -d --build app
```

В конфигурацию существующего Caddy добавить отдельный блок домена с `reverse_proxy dogovorimsya-app:3000` (образец — `deploy/Caddyfile.existing-proxy.example`). Перед изменением сохранить копию исходного файла и проверить конфигурацию. Новый маршрут можно загрузить через `caddy reload`, не останавливая Caddy и другие приложения. Работать только в рамках прав предоставленного SSH-пользователя; при необходимости системных прав root обратиться к владельцу.

Процесс приложения в контейнере работает от пользователя `node`. SQLite и фотографии лежат в постоянном томе `journal_data`; пересборка контейнера их сохраняет. `docker compose down -v` удаляет данные и не является командой обновления.

## После запуска

Проверить HTTPS и редирект с HTTP, вход администратора, выдачу приглашения, регистрацию получателя, отсутствие доступа к чужим правкам и админке, приватность фото после выхода, историю оценок и установку с Safari на экран «Домой». Восстановление по коду проверить на вымышленном аккаунте до использования реальных данных либо вместе с владельцем.

В админке «Доступ» сохранить код или ссылку и передать только получателю. Повторно исходный секрет не показывается. Новый код заменяет старый. Код после регистрации даёт право установить новый пароль этому же аккаунту.

## Обновление

Для доступа через VPN подготовлен вход через существующий HAProxy на `kz-bot`, с сохранением TLS и данных на `ha-vps`: [маршрут, проверки и откат](edge-proxy.md).

Перед обновлением сделать резервную копию данных. Затем получить проверенный коммит, пересобрать и пересоздать только приложение:

```sh
docker compose --env-file deploy/.env up -d --build app
```

Миграции схемы создают новые таблицы без удаления отзывов. Перед будущими изменениями существующих колонок нужны отдельные миграции и проверка резервной копии.

## Пароли и резервные копии

Аварийный сброс пароля администратора в интерактивном терминале:

```sh
docker compose --env-file deploy/.env run --rm app node build/scripts/accounts.js reset reviewer
```

Сброс отзывает предыдущие сессии аккаунта. Для получателя есть аналогичная команда с `recipient`, админка или действующий код восстановления.

Для простой согласованной резервной копии остановить только приложение, сохранить весь том данных и снова запустить приложение. Например, после проверки пути назначения и свободного места:

```sh
mkdir -p backups
docker compose --env-file deploy/.env stop app
docker compose --env-file deploy/.env run --rm --no-deps -T app tar -czf - -C /app/data . > backups/journal.tar.gz
docker compose --env-file deploy/.env start app
```

Если копирование завершилось ошибкой, приложение всё равно нужно запустить последней командой. Копия содержит приватную БД и фотографии; хранить её вне публичного доступа и Git. Сохранение данных только в томе не заменяет резервную копию на другом носителе. Автоматическое расписание резервного копирования пока не настраивалось.
