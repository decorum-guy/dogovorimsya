# Разработка «Договоримся»

## Подтверждено владельцем при старте реализации

Исходные требования из README и фразы сохранены. Дополнительно согласованы шкала 0.0–5.0 с шагом 0.1, обсуждения и реакции для обоих, редактирование своего комментария, история изменений балла и текста, до пяти фото, два закрытых аккаунта с паролями, профили с именами и аватарами. Владелец попросил милый и дерзкий дизайн, особенно огненный для единиц, и по пять вариантов для любого балла.

Шутливые обращения, гендерные формулировки и «вы» в исходных фразах оставлены намеренно. Формальная система апелляций не создавалась.

## Структура

```text
content/homeMessages.json     760 фраз (380 на роль), единый источник

src/lib/ratings.ts           диапазоны и контрастные подписи карточек
server/app.ts                API, авторизация, роли, загрузки
server/db.ts                 схема SQLite и сборка ленты
server/write-receipts.ts     атомарные подтверждения повторяемых запросов
src/lib/journal-sync.ts      порядок чтений/записей и границы сессии

shared/review-history.ts     последняя фактическая смена оценки
server/statistics.ts         общие счётчики пары и пересечение избранного

shared/journal-days.ts       календарные дни по Москве и склонения

scripts/accounts.ts          создание администратора/сброс пароля
scripts/icons.ts             воспроизводимая генерация PNG-иконок
public/                      только публичные ресурсы PWA
tests/                       интеграционные тесты

```

`npm run dev` запускает API и Vite одним процессом на `localhost:3000`. `npm run build` генерирует иконки, проверяет TypeScript, компилирует сервер в `build/` и собирает клиент в `dist/`. `npm start` запускает скомпилированный сервер; production требует `APP_ORIGIN=https://…` и `COOKIE_SECURE=true`. Docker/Compose/Caddy проверены при развёртывании на VPS; реальные адреса и настройки остаются в игнорируемом `deploy/.env`, см. deployment.md.

## Данные и права

В схеме допускается ровно один `reviewer` и один `recipient`. Автор одновременно администратор. Регистрация разрешена только по приглашению, роль берётся из серверной записи кода; смены роли через API нет. Публичная лента и выдача кодов без авторизации отсутствуют. В обычных ответах нет логинов, паролей и хешей; логины доступны только администратору в списке аккаунтов. Пароли хешируются scrypt с индивидуальной случайной солью. Случайный токен сессии находится в HttpOnly/SameSite=Strict cookie; БД хранит только SHA-256 токена. Сессия истекает через 180 дней без использования; при активности срок обновляется не чаще раза в сутки. Изменение/сброс пароля отзывает старые сессии.

Первый аккаунт администратора создаётся в интерактивном терминале; первый посетитель сайта не может назначить себя администратором. В админке выдаётся случайный код со 144 битами энтропии, показанный только в момент выдачи. В БД хранится его SHA-256. На регистрацию неподтверждённого приглашения даётся 30 дней. Активация привязывает код к одному аккаунту атомарно; после этого он служит для восстановления только этого аккаунта, пока не отозван. Повторная регистрация запрещена, в том числе при параллельных запросах.

Новый код отзывает старый код соответствующего аккаунта. Код восстановления — секрет наравне с паролем, поэтому его текст не возвращается в списке кодов. Пригласительная ссылка передаёт его во fragment (`#invite=…` / `#recover=…`), а не в query-параметре серверу; после чтения форма удаляет fragment из текущей записи истории. Код не записывается в localStorage. Лимиты частоты и проверка Origin применяются к регистрации и восстановлению. Администратор может сменить пароль получателя; собственный — через профиль с проверкой текущего пароля или через восстановление/CLI.

Изменяющие API-запросы проверяют Origin на точное совпадение с APP_ORIGIN. В production cookie требует HTTPS; TRUST_PROXY включать только при доверенном локальном прокси. На вход и смену пароля действует ограничение частоты.

Оценки хранятся целыми числами 0–50: значение 49 означает 4.9. Создание и каждая реальная правка атомарно добавляют снимок в историю. Клиент передаёт номер последней версии; при конфликте сервер возвращает 409. Начальный балл не теряется. Версии включают текст, дату и список фото. Старые фото остаются доступны из истории.

Избранное отдельное для каждого аккаунта. Файлы доступны обоим авторизованным участникам пары, включая фотографии из истории и аватары. Вне пары доступа нет.

## Статистика пары

В «Мы вдвоём» доступны дни с регистрации получателя, число отзывов, избранное автора и получателя, пересечение их избранного, текущие пятёрки, комментарии, уникальные фотографии в текущих отзывах, изменения именно балла, повышения относительно первой версии, распределение оценок и четыре вида реакций. Подсчёты общие для пары, а сама отметка избранного остаётся личной. Пересмотр текста без изменения балла не увеличивает счётчик пересмотренных оценок; если балл изменили и вернули обратно, факт пересмотра учитывается.

Дни начинаются с регистрации получателя, а не автора, первой записи или даты деплоя. День регистрации считается первым. Используются календарные дни в Europe/Moscow, одинаково для обоих участников. На открытом экране число дней обновляется раз в минуту и при возвращении в приложение. При возвращении на вкладку/PWA также обновляется bootstrap, чтобы видеть новые счётчики другого участника; приветственная фраза при этом сохраняется.

Схема v3 добавляет `users.registered_at`. Для новых аккаунтов время записывается сервером при регистрации. В существующей базе дата восстанавливается только по самой ранней активации приглашения этого аккаунта, включая отозванные впоследствии коды. Дата выпуска кода восстановления, первый отзыв и время запуска приложения не используются как подмена. Если достоверной даты нет, она остаётся неизвестной. До регистрации второго участника счётчик показывает ожидание, остальные метрики продолжают работать.

Статистика возвращается только в авторизованном bootstrap; хеши кодов, пароли и списки чужих секретов в неё не входят. Персональные флаги избранного возвращаются для текущего пользователя, а для второго — только агрегированные счётчики и общее число совпадений.

## Фотографии

Загрузка ограничена пятью файлами по 16 МиБ. Файл декодируется, проверяется по реальному формату, поворачивается по ориентации и переводится в WebP. Максимальный размер фото — 2000×2000, аватара — 400×400; ограничение декодирования — 40 мегапикселей. EXIF, включая геометки, не сохраняется. SVG и произвольные файлы не принимаются.

JPEG, PNG, WebP и AVIF поддерживаются. HEIC зависит от декодеров установленной сборки libvips: это **не гарантированная функция**. При отсутствии декодера интерфейс просит совместимый формат. На настоящем iPhone эту ветку нужно проверить отдельно.

Имена файлов — случайные UUID. Папка uploads не раздаётся статически: каждый запрос `/media/:id` требует серверную сессию и получает `Cache-Control: no-store`. Отменённые загрузки могут оставаться на диске; автоматическую уборку нужно делать с учётом аватаров и всей истории, чтобы не удалить старые вложения.

## Дизайн

Фразы на главной берутся из content/homeMessages.json: версия 3 содержит по 380 на роль. Все 600 фраз версии 2 сохранены дословно; добавлено по 80 новых с явным матом для каждой роли. `src/lib/message-rotation.ts` перемешивает полный пул алгоритмом Fisher–Yates и выдаёт каждую фразу ровно раз за круг. localStorage хранит оставшиеся индексы, отпечаток содержимого пула и последнюю фразу отдельно по аккаунту/роли. После обновления JSON старые индексы сбрасываются; соседние круги не стыкуются одинаковой фразой. Старый ключ последней фразы учитывается при первом запуске новой ротации. Если хранилище недоступно или переполнено, действует очередь в памяти; между перезагрузками в этом случае история не сохраняется. Между разными устройствами круги независимы.

Фон — тёплая бумага, чернила — сливовые, акценты — розовые, золотые и шалфейные. Шрифты Manrope, Playfair Display и Caveat поставляются локально с кириллицей, внешних запросов к шрифтам нет. Рисунки — локальные SVG; личных фотографий в исходниках нет.

Пять диапазонов: 5.0 золотой, 4.5–4.9 розовый, 3.5–4.4 спокойный, 2.0–3.4 персиковый, 0.0–1.9 огненный. Композиция, типографика, форма и цвет карточек внутри диапазона едины. Автоматически варьируются только маленькие несовпадения: форма надрыва скотча, его ширина/угол/положение, расположение сердечек, звёздочек и рожицы. В огненной серии остаются чертёнок, печать и огонь. Выбор оформления пользователю не предлагается. Набор деталей выбирается сервером один раз при создании, хранится в БД и не прыгает при обновлении или редактировании; настроение следует за текущим баллом.

После новой просьбы владельца контраст распространяется на весь интерфейс: ленту, вход, избранное, профили, статистику, обсуждение, редактор и офлайн-экран. В `shared/ratings.ts` тон идёт от сахарной передозировки до «Пиздец, как полыхает»; крепкие слова относятся к ситуации. Навигация, права доступа и действия остаются понятными. В обоих пулах приветствий по 86 фраз с явным матом: шесть прежних и 80 новых по прямой просьбе владельца. Все предыдущие формулировки JSON сохранены.

## PWA и границы проверки

На iPhone: Safari → «Поделиться» → «На экран „Домой“». Для установки на реальное устройство нужен HTTPS и доступный ему адрес. Манифест, apple-touch-icon, standalone-метатеги и safe-area готовы.

Service worker регистрируется в production и кеширует только публичный экран отсутствия сети, его скрипт и иконку. Приватные данные не доступны офлайн. После потери связи уже открытый экран остаётся в оперативной памяти и показывает баннер; изменения требуют сети. Service worker принимает Web Push и открывает соответствующий отзыв после проверки аккаунта. Подключение устройства и настройки находятся в «Мы вдвоём»; [контракт доставки и проверки](notifications.md).

Автотесты проверяют API на временной SQLite. Встроенный браузер позволяет проверить адаптивный размер iPhone, но не заменяет Safari на настоящем устройстве. Окончательная установка PWA, камера/HEIC и поведение клавиатуры на настоящем iPhone пока не проверялись.

## Резервные копии

Сохранять нужно всю папку DATA_DIR: SQLite, uploads и приватный push-vapid.json вместе. Потеря VAPID-ключей потребует переподключения всех устройств; не генерировать замену поверх сохранённых ключей. При запущенном приложении нельзя просто копировать один app.db, игнорируя WAL. Для простого согласованного бэкапа остановить процесс и скопировать всю папку; для работы без остановки использовать SQLite backup API и согласованную копию вложений. Не добавлять данные и резервные копии в Git. Автоматические бэкапы и инфраструктура не настраивались.

## Исправления аудита

[Аудит от 6 ноября 2026](audit-2026-11-06.md) описывает причины и проверки. Схема v5 добавляет `write_receipts` и `comments.revision` без удаления прежних данных. Номер редакции старого комментария начинается с 1 при миграции; прежний признак редактирования сохраняется по различию исходных временных меток. До миграции сохранить SQLite, uploads и VAPID-ключи.

Создания отзывов и комментариев поддерживают `Idempotency-Key` в транзакции с записью и её push-событием. Ключи принадлежат пользователю; повтор возвращает прежний результат, другой запрос под тем же ключом получает 409. Клиент хранит ключ неопределённо завершившегося запроса только в памяти до повтора; приватные черновики в localStorage не пишутся. Подтверждённая запись остаётся успешной при сбое последующего bootstrap. Реакции нового клиента отправляют желаемое состояние, а не повторяемую команду переключения.

Все чтения ленты проходят через JournalSync: старые запросы и ответы прежней сессии не применяются, промежуточные чтения не перетирают выполняющиеся изменения. Смена пароля обновляет границу сессии и состояние подключения уведомлений. Login и смена пароля повторно проверяют актуальность данных после асинхронного хеширования.
