## Локальный цикл

```sh
npm ci
npm run demo
```

Один процесс обслуживает API и Vite на `http://localhost:3000`. Демо использует отдельную `data/demo`, вымышленные профили и оценки в обе стороны; переключение профиля — в «Мы вдвоём». Настоящие push в demo отключены. Публичная галерея `/design` также содержит только вымышленные примеры.

Для новой приватной локальной базы: скопировать `.env.example` в `.env`, выполнить `npm run accounts`, затем `npm run dev`. Не направлять тестовый запуск на production DATA_DIR. `APP_MODE=demo` принудительно выбирает `data/demo`, разрешён только на loopback и запрещён в production.

`npm run build` генерирует иконки, проверяет TypeScript, компилирует сервер в `build/`, клиент — в `dist/`. `npm start` запускает production-сервер; ему нужны `APP_ORIGIN=https://…` и `COOKIE_SECURE=true`. В Docker тесты выполняются перед сборкой.

## Данные и права

Всего два профиля: уникальные ключи `reviewer` и `recipient` остаются для приветствий, оформления и приглашений. **Оба** создают отзывы. `users.is_admin` независимо разрешает админку; `reviews.author_id` разрешает правку конкретного отзыва. Даже администратор не правит чужой. Первый администратор создаётся CLI setup/bootstrap с явным флагом; регистрация его не выдаёт.

`reviews.recipient_id` — второй участник, назначаемый сервером внутри транзакции создания. Саморецензия запрещена CHECK, адресат связан FK с users. До регистрации второго профиля допускается NULL; миграция/регистрация назначают партнёра ожидающим записям без публикации, истории и push. Клиентские authorId/recipientId/role/isAdmin не дают возможности назначать права или менять направление.

SQLite и изображения находятся в DATA_DIR: `app.db`, при наличии `app.db-wal`/`app.db-shm`, `uploads/`, `push-vapid.json`. Миграции выполняет `openDatabase` при запуске приложения/CLI. Не вызывать эту функцию на production как «безопасное чтение» до бэкапа. Для чтения версии использовать `new DatabaseSync(path, { readOnly: true })`, как в [runbook](deployment.md).

### Аутентификация и приглашения

Пароли — scrypt с индивидуальной солью. Токен сессии — случайный, HttpOnly/SameSite=Strict cookie; БД хранит SHA-256. Сессия живёт 180 дней, продлевается при использовании не чаще раза в сутки. Сброс пароля отзывает сессии и связанные push-подписки; обычная смена пароля создаёт новую текущую сессию.

Код — случайный секрет со 144 битами энтропии, показанный только при выдаче; хранится SHA-256. Неиспользованное приглашение действует 30 дней, после регистрации код привязан к одному аккаунту для восстановления до отзыва. Новый код отзывает прежний. Коды передаются в URL fragment, не query, и не сохраняются в localStorage. В обычном bootstrap нет логинов/секретов; логины доступны только администратору.

Изменяющие API проверяют точное совпадение Origin с APP_ORIGIN; production требует HTTPS cookie. TRUST_PROXY включается только за доверенным локальным прокси. Вход, восстановление, смена пароля и некоторые push-операции ограничены по частоте. После асинхронного хеширования/обработки изображений повторно проверяется актуальность данных/живой сессии.

### Отзыв, комментарий и время

- Балл — целое **0–50**, где 49 = 4.9. Заголовок 1–140, текст отзыва 1–10000 символов; до пяти фото.
- Новая записка получает `eventDate` и `eventTime` по Europe/Moscow при публикации. Повтор подтверждённого POST не меняет момент даже после полуночи. `createdAt` остаётся техническим временем создания.
- PATCH требует актуальную revision и полные поля редактирования; дата/время изменяемы. Старый клиент без eventTime сохраняет существующее время. Лента сортируется по выбранным дате/времени, затем id.
- Создание и настоящая правка атомарно добавляют снимок в revisions. Балл, текст, дата, время, фото и объяснение сохраняются. Отсутствие изменений не создаёт ложную редакцию, устаревшая revision возвращает 409.
- Комментарий содержит текст до 3000 символов и/или до пяти `{id, caption}`; подпись фото необязательна, до 500 символов. Правит только его автор с проверкой revision. PATCH без photos сохраняет вложения, без body — текст. Отдельного журнала всех версий комментария нет; есть номер редакции и updatedAt.
- Избранное персональное, реакции — ❤️ / 🔥 / 😂 / 🥺. Файлы обоим авторизованным участникам доступны, включая фотографии из истории; чужую загрузку или аватар нельзя прикрепить как своё фото.

### Статистика и направления

Основная лента начинается с «Тебе»; «От тебя» — собственные отзывы, «Всё» — общая история. После создания открываются исходящие. Избранное имеет независимое направление, по умолчанию «Всё». Направление применяется вместе с диапазоном, поиском и личной отметкой; это фильтр представления, а не разделение доступа внутри пары.

`statistics.participants`: userId, receivedCount, sentCount, averageRating, perfectCount, ratingDistribution. Средний балл и распределение — по recipient_id. Верхнеуровневые aggregate averageRating/ratingDistribution сохранены для совместимости старого клиента; новый интерфейс не показывает смешанный средний балл пары.

Общие счётчики включают моменты, комментарии, уникальные фото в текущих отзывах/комментариях, избранное каждого и пересечение, реакции, изменения именно балла и повышения относительно первой версии. Исторические фотографии сохраняются, но не входят в счётчик текущих фото, если больше не используются. Пересмотр только текста не считается изменением оценки; возврат к прежнему баллу после изменения учитывается.

Дни — с регистрации профиля recipient, день регистрации первый, календарь Europe/Moscow. Для старых аккаунтов зарегистрированное время восстанавливается только из первой активации приглашения, не из деплоя/отзыва/позднего восстановления. При неизвестной дате показывается ожидание/неизвестность, выдумывать её нельзя.

## API: где искать и как использовать

Типы DTO — [shared/types.ts](../shared/types.ts), точная валидация — [server/app.ts](../server/app.ts), [access.ts](../server/access.ts) и [notifications.ts](../server/notifications.ts).

| Группа | Методы и пути | Доступ |
| --- | --- | --- |
| Состояние и вход | GET `/api/status`, POST `/api/login`, `/api/register`, `/api/recover`, `/api/logout` | Статус/вход публичны; регистрация/восстановление требуют код |
| Лента | GET `/api/bootstrap` | Сессия; весь журнал пары, текущий пользователь, профили, статистика |
| Отзывы | POST `/api/reviews`, PATCH `/api/reviews/:id` | Оба создают; PATCH только автору |
| Обсуждения | POST `/api/reviews/:id/comments`, GET `/api/reviews/:id/comments/version`, PATCH `/api/comments/:id` | Оба читают/пишут; PATCH своему комментарию |
| Отметки | PUT `/api/reviews/:id/favorite`, `/api/reviews/:id/reactions` | Сессия, действие текущего аккаунта |
| Профиль и медиа | PATCH `/api/profile`, POST `/api/profile/password`, POST `/api/uploads`, GET `/media/:id` | Сессия; изменяются свои данные |
| Админка | GET `/api/admin/access`, POST `/api/admin/codes`, `/api/admin/codes/:id/revoke`, `/api/admin/users/:id/password` | is_admin; смена своего пароля — через профиль |
| Уведомления | GET `/api/notifications`, PUT/PATCH `/api/notifications/preferences`, POST/DELETE `/api/notifications/subscriptions`, POST/DELETE `/api/notifications/device`, POST `/api/notifications/test` | Сессия, только свои настройки/устройства |
| Демо-вход | POST `/api/demo/login` | Только локальный APP_MODE=demo, в production маршрута нет |

POST отзыва/комментария поддерживает `Idempotency-Key` (UUID) в одной транзакции с записью, результатом и push. Ключ принадлежит аккаунту, повтор того же содержимого возвращает результат, подмена содержимого/маршрута — 409. Для текстового комментария пустой массив фото сохраняет совместимость прежнего хеша.

POST/PATCH комментария с `Prefer: return=representation` возвращает свежий bootstrap и `Preference-Applied` без хранения всей ленты в receipt. Старый клиент без заголовка получает прежнее подтверждение.

## Синхронизация и UX

JournalSync — общий координатор для сохранения, фокуса, reconnect и push. Сохранение отделено от последующего обновления; старый ответ или 401 прежней сессии не заменяет текущие данные. При изолированном комментарии применяется встроенный bootstrap без второго запроса, при перекрывающихся записях выполняется завершающее чтение. Ручное обновление ждёт выполняющихся сохранений.

Открытое обсуждение раз в пять секунд проверяет маленькую версию комментариев; в фоне проверки пропускаются, при закрытии отменяются. Это не WebSocket/SSE и не фоновая синхронизация всего журнала. Черновики не теряются при переключении истории, просмотре фото или push, но хранятся только в памяти.

Жест вниз начинается только от начала страницы, активируется порогом с сопротивлением и запускает обновление на отпускании. В редакторе/модальном окне/меню отключён, обычной прокрутке и вводу не мешает. Кнопка обновления остаётся доступной. Настоящее поведение Safari требует iPhone.

## Медиа, дизайн и PWA

Загрузка — до пяти файлов по 16 МиБ; аватар один. sharp проверяет реальный формат, ограничивает декодирование 40 Мп, поворачивает изображение, преобразует в WebP без EXIF/геометок: фото до 2000×2000, аватар 400×400. JPEG/PNG/WebP/AVIF поддерживаются; HEIC зависит от libvips. SVG и произвольные файлы не принимаются. UUID-файлы не раздаются статически, `/media/:id` требует сессию и no-store. Отменённые загрузки могут оставаться; уборки пока нет.

Фон `#faf7f2`, чернила `#4e3545`, сливовый `#633d53`, розовые/золотые/шалфейные акценты. Локальные Manrope, Playfair Display, Caveat с кириллицей. Диапазоны: 5.0 gold, 4.5–4.9 rose, 3.5–4.4 paper, 2.0–3.4 ember, 0.0–1.9 inferno. design_variant выбирается сервером один раз (0–4); меняются мелкие детали, настроение следует за текущим баллом.

Приветствия — только content/homeMessages.json, версия 3, 380 на профиль. Перемешанный круг Fisher–Yates, индексы/отпечаток/последняя фраза в localStorage по аккаунту/профилю; при ошибке хранилища — память. Направление отзыва пул не меняет. Все исходные фразы сохранены, контракт — [home-screen-copy.md](home-screen-copy.md).

Service worker регистрируется в production. В Cache Storage — только публичные offline.html/offline.js/icon.svg; личный API и фото туда не попадают. Офлайн-редактирования и постоянного хранения журнала нет. Push показывает только обобщённый сигнал; переход проверяет адресованный аккаунт, существующий черновик не закрывается. Подробности — [notifications.md](notifications.md).

## Миграции и совместимость

Текущая версия схемы — **8**. `server/db.ts` добавляет отсутствующие колонки и таблицы при запуске. Важные этапы:

| Версия | Изменение |
| --- | --- |
| 3 | registered_at, достоверная дата регистрации из приглашения |
| 4 | Настройки, подписки и очередь Web Push |
| 5 | write_receipts и revision комментариев |
| 6 | event_time отзывов/истории из исходного reviews.created_at; не времени редактирования |
| 7 | comments.photos с пустым массивом у прежних комментариев |
| 8 | users.is_admin и reviews.recipient_id, перенос старых прав/адресатов |

is_admin заполняется по прежнему reviewer только при первом добавлении колонки; перезапуск не возвращает отозванные права. Назначение адресата не меняет прежние колонки, время, версии или уведомления. Контракт — [two-way-ratings.md](two-way-ratings.md).

Для следующей миграции поднять версию и добавить проверку перехода с текущей схемы, повторного запуска и сохранения старых значений. Не считать откат старого образа автоматически совместимым со свежей БД: старый код может не понимать поля и устанавливать свой user_version. Бэкап и решение об откате — [deployment.md](deployment.md).
