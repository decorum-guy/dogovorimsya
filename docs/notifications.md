# Уведомления «Договоримся»

Web Push реализован в production, включая оба направления оценок в релизе ddcba5d. Это описание механики; получение на конкретном iPhone не подтверждается автоматически фактом подключения или ответом провайдера. Текущий статус — [status.md](status.md).

## Как подключить

1. На iPhone с iOS 16.4+ открыть сайт в Safari → «Поделиться» → «На экран “Домой”».
2. Запустить именно приложение с его иконки и войти в свой аккаунт.
3. «Мы вдвоём» → «Постучаться в твой космос» → «Подключить» → разрешить уведомления.
4. Нажать «Проверить доставку». Это настоящий зашифрованный Web Push через службу браузера, а не локальный тост.

На поддерживаемых настольных браузерах установка PWA не обязательна. Разрешение не запрашивается автоматически. После отказа нужно изменить его в настройках устройства/браузера. Каждый телефон или браузер подключается отдельно; переключатели событий, общий выключатель, пауза и запрос беззвучной доставки сохраняются для аккаунта и действуют на его подключённых устройствах.

## События

- Новый отзыв и реальное изменение числовой оценки — получателю.
- Новый комментарий — второму участнику, включая ответ автора получателю.
- Новое добавление в избранное и новая реакция — второму участнику.
- Собственные действия, повторный PUT уже установленной звёздочки, снятие отметки/реакции, исправление текста комментария, правка текста отзыва без изменения балла и сохранение без изменений не создают push.

На экране блокировки — только обобщённый сигнал о событии. Личные имена, тексты, заголовки, фотографии и значения оценок в payload не включаются. Нажатие открывает отзыв; авторизация и соответствие аккаунта получателю уведомления проверяются приложением. Открытая PWA получает сообщение без перезагрузки; незавершённая форма остаётся на месте, целевой отзыв ждёт её закрытия. Для закрытого приложения используется ссылка на отзыв, а для ещё не вошедшего пользователя цель сохраняется до входа. Приватные API и фотографии не кешируются.

## Тишина

Общий выключатель останавливает новые отправки на все устройства аккаунта. Категории управляются отдельно. Пауза доступна на 1 час, 8 часов, сутки и неделю; события во время неё пропускаются, а не откладываются. Очередь отменяется при отключении, паузе или выключении категории. Уже принятый службой браузера push отозвать нельзя.

Опция «Просить беззвучную доставку» передаёт `silent: true` в `showNotification` без `vibrate`. Поддержка зависит от браузера/ОС. На iPhone звук надёжно настраивается через «Настройки → Уведомления → Договоримся → Звуки» и «Фокусирование». Пауза в приложении означает прекращение новых отправок, а не фоновый невидимый push: каждый принятый push показывает уведомление, как требует WebKit.

## Сервер

Схема SQLite v4 добавила `notification_preferences`, `push_subscriptions` и `push_outbox`. Старые таблицы и данные не удаляются. Подписка привязана к пользователю и конкретной серверной сессии; выход, истечение или отзыв сессии прекращает доставку, смена аккаунта удаляет прежнюю очередь этого endpoint. Изменения настроек нового клиента передаются частичным PATCH и объединяются на сервере, поэтому переключение одной категории не затирает другую из второго окна. Доставка на устройстве отключается по серверной сессии даже при сбое локального PushManager. Настройки хранятся только в профиле владельца сессии; идентификатор пользователя из тела запроса не определяет адресата.

VAPID-ключи генерируются один раз в `DATA_DIR/push-vapid.json` с правами 0600 и переживают пересборку в постоянном томе. HTTPS-домен приложения используется как VAPID subject; отдельные облачные аккаунты и платные сервисы не нужны. При повреждённом сохранённом файле приложение не подменяет ключи новыми молча. Для восстановления нужен бэкап всего DATA_DIR, включая ключи. Секреты, endpoint и ключи подписок не выводятся в логи и не попадают в Git.

Очередь создаётся в одной транзакции с событием. Один рабочий цикл раз в 5 секунд обрабатывает до 20 заданий, проверяя настройки и сессии перед отправкой. Таймаут — 8 секунд, TTL провайдера — час. При временных сетевых ошибках/429/5xx — до четырёх повторов с увеличением интервала; задания старше суток удаляются. Ответ 404/410 удаляет истёкшую подписку. Повтор после перезапуска сохраняет tag задания, чтобы браузер заменил его при повторном получении. Это доставка с возможными повторами, а не гарантия exactly-once или подтверждение чтения.

API требует сессию и корректный Origin для изменений. Принимаются только HTTPS endpoint служб Apple/Google/Mozilla/Windows, а не произвольные сетевые адреса. Есть лимиты подписок и тестовых запросов. В деморежиме и локальном HTTP реальные отправки отключены; интерфейс настроек можно изучить на вымышленных данных.

## Проверки и пределы

Автотесты проверяют маршрутизацию, изоляцию настроек, отсутствие личного содержимого в push, no-op действия, категории, паузу, очередь, повторную отправку, отзыв подписки и сессии. Отдельно проверяются реальное шифрование/подпись библиотекой Web Push без сетевой отправки, видимое уведомление service worker, silent и безопасная ссылка. Мобильные интерфейсы обоих профилей проверены в локальном браузере.

До подключения реального устройства нельзя подтвердить показ баннера и системный звук именно на нём. Для этого есть кнопка проверки доставки; ответ API «в очереди» не означает, что iPhone уже показал уведомление.

Первичные источники: [WebKit: Web Push на iPhone](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/), [WebKit: Meet Web Push](https://webkit.org/blog/12945/meet-web-push/), [Notifications API](https://notifications.spec.whatwg.org/), [библиотека web-push](https://github.com/web-push-libs/web-push).

После аудита текущая схема — v5: дополнительно сохранены подтверждения создающих запросов и версии комментариев. Уведомление не дублируется при повторе такого запроса с тем же ключом. Истёкший локальный endpoint пересоздаётся при явном переподключении; браузерные операции имеют ограниченное ожидание.


## Взаимные оценки (v8)

Оба профиля выставляют оценки и видят категории «Новый отзыв» и «Изменение оценки». Адресат этих событий определяется reviews.recipient_id. Для комментария, избранного и реакции выбирается второй участник записи относительно инициатора. Исторический role больше не определяет направление доставки. Приглашение/миграция ранее опубликованных записей не создаёт push задним числом. Существующие настройки, привязки сессий и ключи не сбрасываются.
