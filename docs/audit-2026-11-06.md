# Аудит первого UX и надёжности

Исторический отчёт об исходной версии и исправлениях схемы v5. Текущая схема — v8, последующий функциональный релиз включает взаимные оценки; актуальные проверки, ограничения и открытые проблемы — [status.md](status.md).

Исходная версия — `813b97c`. Проверены исходники клиента, API, сессии, загрузка медиа, история, закрытая регистрация, Web Push и миграция базы. Ручные действия выполнялись в отдельном локальном демо с вымышленными записями, без изменения личных отзывов пары.

## Найденные причины и исправления

| Сценарий | Первопричина | Исправление и проверка |
| --- | --- | --- |
| Отзыв сохранён, но интерфейс предлагает отправить снова | POST и последующий bootstrap считались одной неделимой операцией | JournalSync отделяет подтверждённую запись от синхронизации. Сбой чтения показывает предупреждение и повтор обновления, а не ошибку сохранения. Регрессия с потерей сети после успешного POST. |
| Ответ POST потерян после записи; повтор создаёт дубль | У создающих запросов не было устойчивого подтверждения на сервере | Ключ запроса и результат сохраняются в одной транзакции с отзывом/комментарием и push. Повтор возвращает прежний результат; другой запрос с тем же ключом — 409. Проверены параллельные повторы, разные пользователи и маршруты. |
| Старая лента или поздний 401 перетирают актуальное состояние | Независимые чтения при фокусе, push, записи и входе не имели общего порядка | Единый координатор с границами сессии и поколениями чтений; устаревшие ответы отбрасываются. Проверены ответы в обратном порядке и ошибка прежней сессии после нового входа. |
| Быстрые нажатия снимают только что поставленную реакцию | Команда «переключить» не является идемпотентной | Новый клиент отправляет желаемое состояние. Повтор «включить» не выключает реакцию; карточка показывает ожидание и блокирует повторное действие. Старый API остаётся совместимым до обновления клиента. |
| Невозможно нормально набрать дробный балл | Число форматировалось и ограничивалось на каждом символе | Текст ввода отделён от числа в десятых. Поддерживаются точка, запятая и временно пустое поле; некорректный балл не превращается молча в ноль. Проверены `4,9` вручную и граничные значения автоматически. |
| Черновик пропадает при закрытии окна или открытии уведомления | Закрытие не проверяло изменения, а service worker всегда навигировал открытую страницу заново | Проверка несохранённых полей, защита от случайного ухода и блокировка изменяемых полей при отправке. Push передаёт цель без перезагрузки; отзыв ждёт закрытия текущей формы. Цель сохраняется и до входа. Исчезнувшее фоновое окно не поглощает нажатие. |
| Правка комментария из второго окна затирает первую | Отправлялся только новый текст без версии исходного комментария | Версии комментариев и атомарное условное обновление. Устаревшая правка получает 409, текст остаётся в поле. Сохранение неизменённого текста не создаёт ложную отметку редактирования. |
| Пояснение к оценке исчезает, либо показывается `4.9 → 4.9` | Серверный no-op игнорировал отдельное пояснение, а UI приравнивал любую редакцию к изменению балла | Новое пояснение хранится в истории. Для текста показывается «запись обновлена», для оценки — последний реальный переход, включая возврат к исходному баллу. Проверены API и ручное отображение обеих версий. |
| Настройки уведомлений исчезают при сбое браузерной подписки | Загрузка аккаунтных настроек зависела от успешного PushManager | Настройки показываются независимо; ошибка устройства выделяется отдельно. Отключение по серверной сессии работает без локального endpoint. Браузерные операции ограничены по времени; явное переподключение пересоздаёт истёкшую подписку. |
| Переключатель в одном окне сбрасывает другую настройку | Клиент отправлял целиком устаревший объект настроек | Частичный PATCH объединяется с текущими настройками в транзакции. Проверены независимые изменения из двух окон; после смены пароля перечитывается подключение устройства. |
| Проверка логина не соответствует браузерным правилам | HTML pattern компилируется с флагом `v`, где дефис требует экранирования | Общий шаблон HTML/API с правильным экранированием. В браузере проверены допустимый логин с дефисом и недопустимая кириллица. |
| Зависшее ожидание, потерянные заголовки или неверное состояние после ответа прокси | Общий HTTP-клиент не ограничивал ожидание, терял объект Headers и принимал невалидный JSON как успешный объект | Таймауты с отменой, нормализация Headers и явная ошибка чтения ответа. Регрессия проверяет сохранение ключа запроса и отказ от HTML вместо JSON. |
| Пароль или сессия изменились во время асинхронной проверки | Решение принималось по состоянию до длительной операции | Перед созданием сессии повторно проверяется хеш, перед записью пароля — живая исходная сессия и актуальность данных. Проверены отзыв/границы сессии и существующие сценарии восстановления. |
| Узкая навигация, длинные слова и иллюстрация мешают чтению; вход открывается с середины | Минимальные ширины не учитывали 320 px, декоративный блок занимал место текста, прокрутка переживала смену аккаунта | Гибкие кнопки навигации, переносы пользовательского текста, отдельное место подписи, восстановление начала экрана на границе аккаунта и при смене формы входа. Ручная проверка 320×740 и 390×844. |

## Проверки

- Автотесты клиента с управляемым порядком ответов и потерей связи.
- Интеграционные проверки реального HTTP API на временной SQLite: регистрация/восстановление, права, медиа, история, повторы, конфликты и уведомления.
- Миграция имитированной v4 с прежними аккаунтом, сессией, избранным, настройками и исправленным комментарием; повторный запуск сохраняет результат.
- Ручная проверка обоих профилей: ввод оценки, создание отзыва, отмена закрытия черновика, комментарий и его правка, избранное каждого, история, переключатели, выход и регистрационная форма.
- Исходные 760 фраз и название/слоган сохранены.

Production-сборка выполняет тесты, TypeScript-проверку и загрузку модулей/чтение PWA-ресурсов от непривилегированного пользователя. Перед применением схемы v5 требуется полная резервная копия SQLite, фотографий и VAPID-ключей. После обновления — HTTPS, приватные API, целостность базы и сверка прежних данных по исходным колонкам.

## Границы

Черновики защищены от случайного закрытия, но не записываются в постоянное браузерное хранилище. Принудительное завершение PWA операционной системой может уничтожить ещё не отправленный текст. Реальные iOS-клавиатура, камера/HEIC, системные разрешения, показ push и звук требуют физического iPhone; локальный размер экрана их не эмулирует. Это проверка перечисленных сценариев, а не обещание отсутствия любых будущих ошибок.

Правила HTML pattern: [стандарт HTML](https://html.spec.whatwg.org/multipage/input.html#the-pattern-attribute), [справочник MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/pattern). Ограничения push на iPhone: [WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).
