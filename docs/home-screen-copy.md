# Главный экран: случайные фразы по ролям

## Зафиксированная идея

У приложения **«Договоримся»** слоган **«Оценки обсуждаются»**. На главном экране появляется короткая случайная фраза — ироничная, нежная или слегка дерзкая, в эстетике переговоров, рецензий и апелляций.

**Для каждой роли — собственный пул**, а не единая подборка:
- `reviewer` — человек, который пишет и правит оценки. Фразы обращены к нему на «ты».
- `recipient` — человек, которому ставят оценки и который может просматривать записи и отвечать. Фразы обращены к ней на «ты».

**Источник текстов:** [`content/homeMessages.json`](../content/homeMessages.json) — 380 фраз для каждой роли, 760 всего, версия 3. Все предыдущие 300 фраз каждой роли, включая исходные 26, сохранены дословно и в прежнем порядке. По прямой просьбе владельца добавлено по 80 новых фраз с явным матом; теперь таких по 86 в каждом пуле.

Обязательная фраза для `recipient`: **«Обжалуй меня.»** Это шутливый заголовок, а не требование немедленно реализовать систему официальных апелляций.

## Поведение для реализации

1. После авторизации приложение определяет роль **по серверной сессии / правам доступа**, а не по ненадёжному выбору пользователя на клиенте.
2. Когда пользователь **открывает главный экран**, выбирается одна случайная фраза только из массива его роли. При простом перерисовывании интерфейса она **не должна** беспричинно меняться.
3. В пределах браузера каждый аккаунт проходит перемешанный круг своего пула без повторов. После всех 380 фраз начинается новый случайный круг; первая фраза не совпадает с последней предыдущего круга. Очередь сохраняется в localStorage отдельно по аккаунту и роли, поэтому перезагрузка не начинает круг заново. Изменение пула сбрасывает устаревшие индексы. При недоступном хранилище очередь работает в памяти текущей страницы. История на сервере не ведётся.
4. Текст показывается крупно, но не мешает содержимому ленты, не вызывает скачков вёрстки; переносы строк и длинные фразы проверить на узких экранах iPhone.
5. Фразы хранятся в одном централизованном файле; в компонентах не дублируются. Локаль первого выпуска — русский.
6. Для двух ролей проверить корректное разделение пулов, отсутствие пустого текста, отсутствие скачка фразы при реакциях/комментариях и корректный fallback, если массив пуст.
7. Если появится кнопка «другая фраза» — согласовать это отдельно; она **не входит** в подтверждённые требования.

## Тональность

- Юмор про **переговоры, отзыв, 4.9 → 5.0, обжалование, справедливость, объятия, милоту**.
- Не превращать честные оценки в «обязательно ставить 5»; любовь не сводится к рейтингу человека.
- Лёгкая романтическая ирония лучше токсичных/унижающих формулировок.
- По просьбе владельца расширенный пул смешивает переговорный абсурд, бытовые ситуации, космос, флирт, очень нежные и очень дерзкие формулировки, в том числе отдельные фразы с матом. Дерзость направлена на ситуацию и взаимную игру, а не на унижение партнёра.
- Фразы должны читаться как персональное приветствие, а не как реальные оценки в ленте.

## Пример композиции

**Договоримся**

*Оценки обсуждаются*

> Обжалуй меня.

Далее — главная лента/действия согласно роли. Не обязательно использовать этот пример как финальный макет.
