## Открытая сетевая проблема

**Не считать доступ из РФ окончательно исправленным.** Повторная проверка 7 ноября дала:

| Маршрут с Mac | Результат |
| --- | --- |
| Прямой, Cloudflare подтвердил RU, обычное разрешение домена в `38.244.134.21` | `/api/status` и HTML — 200, но большой клиентский скрипт не загрузился за 20 секунд: curl exit 28, несмотря на заголовок 200 |
| Тот же прямой маршрут с `--resolve dogovorimsya.online:443:95.142.42.46` | Скрипт получен полностью: **399350 байт**, около 0.075 с |
| Через HTTP Happ `127.0.0.1:10809`, Cloudflare подтвердил GB | Статус, HTML и полный скрипт получены; скрипт около 1.08 с |

У успешных загрузок один SHA-256: `b888188611ed90b00b9b2abb3f610b23bfc69d68c5809c97e9b03fc38ef55285`, ресурс `/assets/index-CMVHxqtU.js` релиза `ddcba5d`. Размер указан после распаковки HTTP-сжатия. Это измерение конкретного клиента, а не обещание постоянной скорости.

Сайт и origin работают; маршрут RU-клиента через KZ остаётся проблемным. Причина выбора KZ конкретным Mac ещё не установлена: возможны выбор/география резолвера и кеш, но это **гипотезы**. Из этих данных нельзя заключать о неисправности участка KZ → origin. Географическое правило DNS не гарантирует страну реального HTTP-клиента.

Следующий разбор: сопоставить обычный DNS Mac с ответами обоих авторитетных NS и ECS, повторить полные загрузки из RU/через Happ и проверить устойчивость выбора маршрута. Сначала диагностика; не менять NS, firewall, HAProxy или Caddy и не использовать root без отдельного разрешения. Порядок проверки — [edge-proxy.md](edge-proxy.md), ограничения — [geodns.md](geodns.md).

## Что остаётся проверить или реализовать

Это ограничения и открытые работы, не автоматически утверждённый новый объём разработки:

- На физическом iPhone: установка/обновление PWA, клавиатура, камера/HEIC, жест обновления, системное разрешение, получение push и звук. Браузерные проверки и mock-провайдер в тестах не подтверждают это.
- HEIC зависит от декодеров установленной сборки libvips; совместимый JPEG/PNG/WebP/AVIF остаётся доступным вариантом.
- Полноценного офлайн-журнала и постоянных приватных черновиков нет. Память страницы не защищает от принудительного завершения приложения ОС.
- Автоматическое расписание бэкапов и отдельное внешнее хранилище в рамках проекта не настраивались. Ручная копия на том же VPS не заменяет независимый бэкап.
- Автоматического обновления базы стран DB-IP и уборки неиспользуемых загрузок нет. Уборка обязана учитывать аватары, комментарии и всю историю отзывов.
- CI workflow, автоматический деплой, формальные апелляции, публичный сервис и больше двух участников не реализованы. Не добавлять их только из шуток в интерфейсе.

## Как работать дальше

Проверить Git-статус и исходный контракт, запустить отдельное локальное демо, воспроизвести проблему на вымышленных данных. При изменении логики выполнить подходящие тесты и сборку; при миграции дополнительно сравнить прежние данные, фотографии, сессии и ключи на тестовой базе. Новые пользовательские функции обсуждать с владельцем; существующие данные и инфраструктуру сохранять. Для правки только текста проверять документацию, без рестарта production.
