# CLAUDE.md — контекст проекта «Договоримся»

> Этот файл — стартовые инструкции для Claude (и других ИИ-разработчиков), работающих с репозиторием.

## Перед началом работы

1. Прочитай `README.md` целиком — там зафиксированы название, смысл, функции и ограничения.
2. Прочитай `docs/home-screen-copy.md` — там точные требования к случайной надписи на главной странице.
3. Прочитай `content/homeMessages.json` — это **единый источник** фраз, строго разделённых по двум ролям.
4. Проверь действительные файлы и состояние Git-ветки; не считай, что код уже есть. При первом чтении здесь были только продуктовые документы.
5. Не меняй утверждённое название и слоган без прямой просьбы владельца.

## Установленные продуктовые решения

- **Название интерфейса:** «Договоримся».
- **Слоган:** «Оценки обсуждаются».
- **Формат:** приватное мобильное PWA для двоих, в первую очередь iPhone.
- **Роли:** `reviewer` (создаёт/изменяет честные оценки) и `recipient` (смотрит, комментирует/реагирует).
- **Отзыв:** звёздная оценка с десятыми (например, 4.9), текст, возможность прикрепить фото, дата.
- **Изменения:** история редактирования оценки, например 4.9 → 5.0; исходное значение и факт изменения не терять.
- **Профили:** имена, аватары, аутентификация.
- **Стиль:** милый, аккуратный, ироничный; оформление карточек может зависеть от диапазона оценки.
- **Заголовок на главной:** случайный по роли, из `content/homeMessages.json`. В пуле для `recipient` обязательно «Обжалуй меня.»; не менять заголовок на каждом реактивном ререндере.
- **Безопасность:** поскольку данные интимно-личные, а репозиторий публичный, не коммить реальные фотографии, отзывы, имена, секреты, пароли, дампы БД, токены и .env.

## Не домысливай как утверждённое

- Кнопка/процесс формальной апелляции — **не согласован**; «Обжалуй меня» пока шутливая фраза.
- Язык, стиль реализации, фреймворк, схема БД, провайдеры авторизации, домен, VPS и деплой — **ещё не закреплены здесь**.
- Продукт ещё не реализован автоматически от появления этих документов.
- Изначальные тексты 52 фраз были предложенным стартовым набором; последующие решения владельца о сохранении и расширении зафиксированы ниже.

## Уточнения после поручения на реализацию

Владелец подтвердил рекомендации и прямо поручил кодить: шкала 0.0–5.0 с шагом 0.1; комментарии и реакции обоим, правки только своего комментария; история балла и текста; до пяти фотографий; два закрытых аккаунта; тёплый дизайн блокнота. Отдельно запросил дерзкое огненное оформление для единиц и по пять вариантов карточки для любого балла.

Исходные фразы **сохранить без редакторских исправлений**: обращения на «вы» и гендерные шутки владельца устраивают. Актуальная реализация и технические решения описаны в README и docs/development.md.

Последующие уточнения владельца: пять вариантов нужны только для мелкого разнообразия. Использовать общий стиль первых трёх образцов; менять надрывы/положение скотча, расположение сердечек, звёздочек и рожиц, а не всю композицию. Выбора оформления пользователем нет.

Добавить закрытую регистрацию по кодам: один код создаёт один аккаунт и потом служит для восстановления его пароля. У автора есть простая админка для выдачи/отзыва кодов и смены пароля получателя. Первая учётная запись администратора создаётся локальной серверной командой. Длительная сессия PWA продлевается при использовании. Владелец поручил переходить к развёртыванию после этих правок и обещал предоставить домен и SSH; до их получения не домысливать адреса и доступы.

## Фактическое развёртывание

MVP развёрнут из ветки `codex/mvp` на VPS владельца, в отдельном контейнере и постоянном томе. Используется существующий Caddy; его конфигурация сохранена перед добавлением отдельного маршрута. Проверены Linux-сборка, тесты, HTTPS, отсутствие демовхода в production, приватные API и сохранение работы прежних сервисов. Первый аккаунт создан через CLI bootstrap; его секрет передаётся только владельцу и никогда не попадает в Git.

Работать на сервере только предоставленным SSH-пользователем. Владелец отдельно запретил самостоятельно выполнять действия от root: если такие права понадобятся, объяснить конкретное действие и обратиться к нему. Не перезапускать и не перенастраивать посторонние сервисы ради приложения.

## Статистика и избранное

По просьбе владельца в «Мы вдвоём» добавлены общие метрики пары и календарный счётчик с дня регистрации получателя (первый день — день регистрации, общий часовой пояс Europe/Moscow). До неё показывать ожидание, не начинать отсчёт с автора или деплоя. Звёздочка у отзыва и в его подробностях управляет личным избранным текущего аккаунта; счётчики автора, получателя и совпадений видны обоим. Существующие пароли, сессии, приглашения, отзывы и отметки при обновлении сохранять. Перед миграцией live-базы сделать резервную копию.

## Расширенный пул приветствий

Владелец попросил очень большой, разнообразный пул: креативные, абсурдные, дерзкие, ультрадерзкие и ультрамилые фразы для каждой роли. Версия 2 содержит по 300 фраз, 600 всего; первые 26 каждой роли сохранены дословно. Отдельные новые фразы с матом соответствуют этой просьбе. В одном браузере выдавать весь перемешанный круг без повторов, сохранять его по аккаунту/роли после перезагрузки и избегать одинаковой фразы на стыке кругов. Не менять фразу при реакциях, комментариях и других ререндерах; не добавлять кнопку смены фразы без отдельной просьбы.

## Контраст интерфейса и уведомления

Владелец прямо попросил перенести космос, приторную милоту, дерзость и местами сильный мат на весь интерфейс для обоих. Не сводить весь сайт к одинаковой нежности; названия действий и ошибки должны оставаться понятными. Баланс пула проверен: по 300 фраз на роль, по шесть с явным матом. Название, слоган и исходные фразы не менять.

Согласованы Web Push: получателю — новый отзыв и реальное изменение балла, обоим — новые комментарии, добавления в избранное и реакции другого человека. Подключение только после нажатия пользователем, отдельно для каждого устройства. Настройки аккаунта: категории, общий выключатель, временная пауза и запрос silent. iOS может игнорировать silent; не обещать управление системным звуком. Не выдавать успешную отправку провайдеру за подтверждение получения на iPhone. Текст отзывов, баллы и фотографии не класть в push. При выходе/сбросе пароля привязанные к сессии подписки отзываются. Схема v4 и VAPID-ключи живут в приватном томе; перед миграцией сделать бэкап, ключи и подписки никогда не коммитить. Технический контракт — docs/notifications.md.

## Если задача — начать разработку

Сначала дай краткий обзор того, что уже существует в коде, а чего нет. Предложи минимальный, безопасный план MVP и структуру проекта; после согласования или прямого поручения можно писать код. Особое внимание — разделению ролей, приватности фотографий и отзывов, непрерывности истории редактирования, удобству PWA на iPhone. Не выполняй деплой и не придумывай доступы к серверу без явных данных.
