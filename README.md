# Договоримся

**Оценки обсуждаются.**

«Договоримся» — личное, немного ироничное веб-приложение (PWA) для двоих. Один человек ставит другому **честные** оценки за небольшие события и ситуации, а второй может читать отзывы, комментировать и реагировать. Идея выросла из разговора об оценках на занятиях по переговорам: а что, если у отношений появится собственная «зачётка» — с тёплым юмором, звёздами и возможностью пересмотреть оценку?

## Продуктовые договорённости

- **Название:** Договоримся
- **Короткое описание / слоган:** Оценки обсуждаются
- **Формат:** mobile-first PWA, удобно открывать с домашнего экрана iPhone.
- **Аудитория:** два приватных профиля — автор оценок и получатель оценок; у каждого имя и аватар.
- **Отзывы:** оценки звёздами по шкале до 5, включая десятые (например, 4.9); текст/заголовок, фотографии, дата.
- **Изменение оценки:** возможна правка; сохраняется история изменений и видимое обозначение вроде «4.9 → 5.0, изменено».
- **Права:** автор создаёт и редактирует оценки; получатель видит их и может оставлять комментарии/реакции. Не смешивать права ролей.
- **Оформление:** милое, игривое, с вариантами карточек для разных диапазонов оценок; эстетика романтики + переговоров, без «карательной» серьёзности.
- **Главная страница:** при её открытии показывать случайную короткую фразу из **разных пулов** для автора и получателя. Фраза «Обжалуй меня» обязательна в пуле получателя. Предложенный стартовый набор и поведение: [docs/home-screen-copy.md](docs/home-screen-copy.md).
- **Принцип:** оценки должны быть честными; юмор и возможность обсуждения не должны превращать балл в требование его повысить.
- **Приватность:** отзывы, комментарии, аватары и фотографии доступны только авторизованной паре, а не публично. Репозиторий может быть публичным, личные данные — нет.

## Статус

Реализован и развёрнут **приватный MVP**: React + TypeScript, Express, SQLite и закрытое хранение фотографий. Production работает в Docker за Caddy с HTTPS; приложение и база отделены от исходников.

### Что работает

- Два аккаунта с серверными ролями. Закрытая регистрация по приглашению: один код создаёт один аккаунт, затем подходит для восстановления его пароля. Админка автора позволяет выдавать/отзывать коды и менять пароль получателя.
- Вход сохраняется в PWA: сессия на 180 дней продлевается при использовании. Пароль или код позволяют вернуться после завершения сессии.
- Оценки **0.0–5.0, шаг 0.1**, заголовок, текст, дата события и до пяти фотографий.
- Правки только автором. Все версии балла, текста, даты и фотографий сохраняются; устаревшая вкладка не может затереть новую версию.
- Комментарии и четыре реакции доступны обоим; редактировать можно только собственный комментарий.
- Личное избранное со звёздочкой на карточке и в открытом отзыве: у каждого свой список. Фильтры ленты, поиск на широких экранах, имена и аватары профилей.
- «Мы вдвоём»: дни с регистрации получателя, отзывы, избранное каждого и совпадения, пятёрки, фотографии, комментарии, реакции, пересмотренные оценки и распределение баллов. День регистрации — первый; до неё счётчик ждёт второго участника.
- **Единый стиль бумажных карточек** с пятью автоматическими наборами мелких деталей: надрывы, угол и положение скотча, сердечки, звёздочки и рожицы. Цвет и настроение зависят от балла. Детали сохраняются за отзывом; выбирать дизайн вручную не нужно.
- 600 коротких фраз: по 300 для каждой роли, от ультрамилых до дерзких и абсурдных. В браузере проходит весь перемешанный пул прежде, чем начнутся повторы; круг сохраняется после перезагрузки. Фраза остаётся прежней при обычном ререндере.
- PWA-манифест, PNG-иконки для iPhone, safe-area, отдельный экран отсутствия сети. Личные ответы API и фотографии не кешируются service worker.
- Контрастный голос интерфейса для обоих: от приторной нежности до космического абсурда и крепких слов. Подписи карточки и подсказки редактора зависят от балла; название и слоган прежние.
- Web Push: ей — новые отзывы и изменения балла; обоим — новые комментарии, добавления в избранное и реакции другого человека. В «Мы вдвоём» есть подключение каждого устройства, выбор событий, общий выключатель, пауза на час/8 часов/сутки/неделю и запрос беззвучной доставки. Текст отзыва, фото и балл в push не отправляются. На iPhone нужны iOS 16.4+ и запуск PWA с экрана «Домой»; звук зависит от iOS. [Подробнее](docs/notifications.md).

### Быстрый просмотр без личных данных

Нужен **Node.js 24+** и npm.

```sh
npm ci
npm run demo
```

Открой `http://localhost:3000`. Демо автоматически входит как автор; в «Мы вдвоём» можно посмотреть приложение глазами получателя. Все записи вымышленные, изображение завтрака — иллюстрация. Демо хранится отдельно в игнорируемой папке `data/demo`, работает только на loopback-интерфейсе и запрещено в production.

Галерея деталей: `http://localhost:3000/design`. Например, `/design?tone=inferno` показывает пять карточек единицы с маленькими различиями; `gold`, `rose`, `paper`, `ember` — остальные настроения. Это демонстрация автоматических деталей, не экран выбора оформления. Галерея содержит только вымышленные образцы.

### Своя пара локально

```sh
cp .env.example .env
npm run accounts
npm run dev
```

Команда интерактивно создаст первый аккаунт автора-администратора. После входа открой «Доступ», выдай приглашение и передай код или ссылку получателю. По коду она создаст собственный аккаунт; этот же код подходит для восстановления пароля. Можно иметь только одного автора и одного получателя. Пароли не отображаются в терминале и не передаются аргументами команд; предустановленных паролей нет.

Пароль можно поменять в профиле, восстановить по действующему коду или сбросить из терминала: `npm run accounts -- reset reviewer` / `recipient`. Сброс завершает предыдущие сессии. Новый код заменяет старый; исходный текст кода показывается администратору только при выдаче.

Для первого входа без задания пароля в SSH есть `npm run accounts -- bootstrap`: только на пустой базе создаётся автор с логином `owner` и выдаётся стартовый код восстановления. Владелец задаёт свой пароль через сайт, имя меняет в профиле. Стартовый код показывается только вызывающей сессии и не хранится в исходниках.

### Проверки

```sh
npm test
npm run build
```

Интеграционные тесты используют временную базу и проверяют приглашения, восстановление, отзыв кодов, права админки, историю, обработку фото, комментарии, реакции, продление сессий и разделение фраз.

Для VPS подготовлены Dockerfile, Compose и Caddy с HTTPS: [порядок развёртывания](docs/deployment.md). При сборке production-контейнера выполняются интеграционные тесты. Проверены публичный HTTPS, HTTP-редирект, закрытые API, ресурсы PWA и мобильная вёрстка; установка на настоящий iPhone проверяется владельцем.

Подробности: [разработка и хранение данных](docs/development.md). Для ИИ-разработчика также прочитай [CLAUDE.md](CLAUDE.md) и исходные документы продукта. Не описывай планируемое как реализованное.
